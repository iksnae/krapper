# Coverage

## Record, then score

Run a trusted test-and-coverage command through Krapper. For example, from a Go module root:

```sh
krapper --coverage-command 'mkdir -p target/coverage/go && go test ./... -coverprofile=target/coverage/go/coverage.out'
krapper --threshold 5
```

The command must exit zero, regenerate **all** recognized reports, and leave source/test/configuration inputs unchanged. Krapper then saves `.metrics/coverage-receipt.json`. Later runs verify the checkout, input hashes and report hashes before scoring.

Remove stale reports or have the producer replace them atomically. Freshness uses the filesystem clock and pre/post report metadata; an indistinguishable rewrite is rejected. Changes to non-generated files—including documentation—require a new run. Put generated output in excluded build or coverage directories. Changing a receipt by hand is not verification.

A failed recording command invalidates the receipt and preserves the previous score snapshot. That old snapshot is not evidence of the failed run. Empty selections and unavailable function measurements cannot pass threshold gates.

## Report locations

| Language | Input |
| --- | --- |
| Go | `coverage.out` or `target/coverage/go/coverage.out` |
| TypeScript / JavaScript / Svelte | `coverage/**/lcov.info` or `target/coverage/**/lcov.info` |
| Rust | LCOV in those same directories; generate it with an installed tool such as `cargo llvm-cov` |
| Swift | LLVM JSON in `target/coverage/swift/*.json`; LCOV also works outside Swift packages |
| Python | LCOV generated by coverage.py |
| Java | `target/site/jacoco/jacoco.xml` |
| Clojure | Cloverage HTML under `target/coverage/`, or LCOV |

For multiple modules, keep reports under the analyzed root with unambiguous source paths. Go and JaCoCo report discovery reaches only two nested module levels. See the [loader](../src/crapper/coverage.py) for exact discovery rules.

## Swift packages

Strict mode supports one Swift package at `--root`. Your coverage command must produce:

- `target/coverage/swift-package.json`: output of `swift package describe --type json`.
- `target/coverage/swift/*.json`: LLVM exports containing test-source records from **every declared test target**, with paths inside this checkout.

Merge the raw profiles and export against all test binaries. SwiftPM's automatic `--show-codecov-path` export can contain only one binary, so do not assume it is complete. Krapper checks target representation, not whether every test actually executed. LCOV alone cannot establish Swift package completeness. Xcode export conversion is manual; Krapper does not perform it.

The Swift reader was adapted from [felipearpa's upstream contribution](https://github.com/unclebob/crapper/pull/35).

## Limits

- Receipts detect accidental stale or mixed evidence, not deliberate forgery, bad assertions, or changes to external toolchains/dependencies. Trust the command you run. Do not recursively invoke strict Krapper inside that command before its receipt exists.
- `--allow-unverified-coverage` warns and permits exploratory scoring of old reports. It cannot be combined with `--threshold` or `--coverage-command`; stale merged reports can inflate coverage.
- Svelte components are scored through their top-level `<script>` blocks only. Markup (`{#if}` blocks, inline handlers) and callbacks passed to `$effect`, `$derived.by` or `$:` statements have no entry. Instance-script functions are covered only when a test mounts the component.
- Unsupported files and top-level code without a function entry are not scored. Overloads can share namespace/name keys in EDN output.
- Test/build/dependency paths are excluded by default; `krapper --help` lists the rules. Explicitly naming a test file includes it.
- Directories named `build`, `coverage`, `dist`, `out` or `target` are skipped as build output only when git ignores them or they sit directly under the project root; elsewhere they are source. Add nested output directories to `.gitignore`, or they are scored and bound into the receipt. Outside a git checkout these names are skipped at any depth. Krapper warns when a directory skipped by name alone holds source files. Git's answer stops at submodules and nested repositories: an output directory inside one is scored unless the outer repository ignores it.
- Raw Python parser/coverage APIs do not enforce provenance. Only the CLI does.
